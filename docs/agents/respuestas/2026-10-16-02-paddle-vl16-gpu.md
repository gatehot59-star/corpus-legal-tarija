## Falsadores y recibos

`heldout.py` puntuó cada salida completa y el verificador distinto, Myers bit-parallel, recalculó las distancias, denominadores y agregaciones. Ambos salieron con exit 0 para cada motor. Cada verificación contrastó 200 pares artificiales y cinco casos conocidos, y rechazó cinco mutaciones: página faltante, texto cambiado, score cambiado, hash de imagen cambiado y hash de gold cambiado.

La independencia es del algoritmo/instrumento: **el operador fue el mismo; esto no es auditoría externa**. El adaptador pasó cinco fixtures. La preparación corregida rechazó manifiesto ausente y manifiesto alterado, y reprodujo los seis archivos exactos del dataset expandido.

Afirmación → instrumento → posibilidad de rojo → estado:

- Cinco páginas completadas → estado, cinco predicciones, recibo del proceso y evaluador de cobertura → sí → PASS.
- Parámetros en GPU → Paddle y `nvidia-smi`, guard sin fallback → sí → PASS.
- Menor CER en este banco → evaluador congelado y segundo algoritmo → sí → PASS contra referencia IA.
- Exactitud jurídica certificada o despliegue listo → estos instrumentos no lo prueban → NO MEDIDO.

La evidencia adjunta en Git conserva las diez transcripciones de salida completas, hashes de entrada, resultados por página, comprobaciones y recibos esenciales. ## Fallos preservados y recuperación

Versión 1: se supuso un `bank.zip` montado, pero Kaggle lo había descomprimido automáticamente. Falló antes de instalar; se verificaron después los seis archivos y sus hashes.

Versión 2: `venv` falló en `ensurepip`. Se pasó a un venv sin pip administrado por el pip existente con `--python`; no se actualizó el entorno base.

Versión 3: instaló dependencias, verificó pesos y cargó el modelo en GPU, pero falló antes de inferir páginas por ausencia de DejaVuSans en el calentamiento. La versión 4 usó la fuente incorporada de Pillow, con prueba de renderizado. Sólo cambió esa imagen sintética de calentamiento; el banco jurídico, modelos y parámetros de generación quedaron iguales.

Los fallos 1 a 3 no se cuentan como lecturas OCR exitosas. El FAIL CPU previo de 3/5 y su timeout de 1.800 s siguen vigentes. La alternativa de menor resolución no se ejecutó.
